# Регламент тестирования

## 1. Общие положения
- Тестировщики отвечают за:
  - написание unit‑тестов (бэкенд);
  - ручное тестирование бизнес‑кейсов в ветке `stage`;
  - проверку работоспособности API и клиентов.
- Все тесты запускаются **перед** слиянием `dev` → `test` и `test` → `stage`.

## 2. Unit‑тесты
- Фреймворк: `pytest`.
- Тесты располагаются в папке `backend/tests/`.
- Каждый новый эндпоинт или функция бизнес‑логики должны покрываться unit‑тестами.
- Тестировщики пишут тесты совместно с разработчиками, но контроль за полнотой — у тестировщиков.
- Перед слиянием `dev` → `test` все тесты должны быть зелёными.

## 3. Ручное тестирование в ветке `stage`
- После слияния `test` → `stage` тестировщики разворачивают приложение локально или на тестовом стенде.
- Проверяют каждый бизнес‑кейс, составленный аналитиками.
- Если найдена ошибка:
  - создаётся **Issue** на GitHub с описанием шагов воспроизведения, ожидаемого и фактического результата.
  - Разработчик исправляет в своей feature‑ветке, затем через `dev` → `test` → `stage` фикс доставляется повторно.
- Только после успешного ручного тестирования тим‑лид даёт добро на слияние `stage` → `prod`.

## 4. Формат отчёта о тестировании
Для каждого прецедента тестировщики заполняют таблицу.
