# Семантика ER-диаграммы

> Версия: 1.0  

## 1. Таблица `client` (Клиент)

Хранит всех пользователей системы: обычных покупателей, менеджеров и администраторов.

| Поле | Тип | Описание | Примечания |
|------|-----|-----------|-------------|
| `client_id` | SERIAL (INT) | Уникальный идентификатор клиента | Первичный ключ |
| `full_name` | VARCHAR(200) | Полное имя клиента | Обязательное поле |
| `phone` | VARCHAR(20) | Номер телефона | Обязательное, для связи |
| `email` | VARCHAR(100) | Адрес электронной почты | Уникальный, обязательный, используется для входа |
| `address` | TEXT | Адрес доставки | Может быть пустым, но для заказа нужен |
| `reg_date` | DATE | Дата регистрации | По умолчанию текущая дата |
| `role` | VARCHAR(20) | Роль в системе | Допустимые значения: `'client'`, `'manager'`, `'admin'`. `'client'` по умолчанию |
| `total_purchases_amount` | NUMERIC(10,2) | Общая сумма всех покупок клиента за всё время | Обновляется автоматически при оформлении заказа. Нужна для определения постоянного клиента (>5000 руб.) |

**Связи:**
- Один клиент может иметь много заказов (`1 : N` с таблицей `orders`).

**Бизнес-правило:**  
Если `total_purchases_amount` ≥ 5000, клиент считается постоянным и получает скидку 2% на **каждый новый заказ**. Скидка применяется при расчёте `total_amount` нового заказа.

## 2. Таблица `product` (Товар)

Содержит товары, которые продаются в интернет-магазине.

| Поле | Тип | Описание | Примечания |
|------|-----|-----------|-------------|
| `product_id` | SERIAL (INT) | Уникальный идентификатор товара | Первичный ключ |
| `name` | VARCHAR(200) | Название товара | Обязательное |
| `price` | NUMERIC(10,2) | Цена за одну единицу товара | Текущая цена (может меняться) |
| `unit` | VARCHAR(10) | Единица измерения | Значения: `'шт'`, `'кг'` |
| `stock_quantity` | NUMERIC(10,2) | Количество товара на складе | |

**Связи:**
- Один товар может входить во множество заказов (через таблицу `order_item`). Связь `1 : N`.

---

## 3. Таблица `orders` (Заказ)

Фиксирует факт продажи (заказа) одним клиентом.

| Поле | Тип | Описание | Примечания |
|------|-----|-----------|-------------|
| `order_id` | SERIAL (INT) | Уникальный номер заказа | Первичный ключ |
| `client_id` | INT | Идентификатор клиента, сделавшего заказ | Внешний ключ → `client(client_id)` |
| `sale_date` | TIMESTAMP | Дата и время оформления заказа | По умолчанию `CURRENT_TIMESTAMP` |
| `delivery_date` | DATE | Ожидаемая или фактическая дата доставки | Может быть `NULL`, если ещё не доставлен |
| `total_amount` | NUMERIC(10,2) | Итоговая сумма заказа **после применения скидки** | Рассчитывается программно на основе `order_item.price_at_sale * quantity` и скидки клиента |
| `status` | VARCHAR(30) | Статус выполнения заказа | Значения: `'new'`, `'processing'`, `'shipped'`, `'delivered'`, `'cancelled'`. По умолчанию `'new'` |

**Связи:**
- Заказ принадлежит одному клиенту (`N : 1` к `client`).
- Один заказ содержит много товаров (`1 : N` через `order_item`).

**Бизнес-правила:**
- При создании заказа:
  - Для каждого товара фиксируется `price_at_sale` (текущая цена из `product.price`).
  - Рассчитывается `total_amount` = сумма (`price_at_sale * quantity`) по всем позициям.
  - Если `client.total_purchases_amount` ≥ 5000, из `total_amount` вычитается 2% (скидка постоянного клиента).
  - После оформления заказа `client.total_purchases_amount` увеличивается на `total_amount`.
- Изменение цены в `product` не влияет на уже оформленные заказы, так как цена сохранена в `price_at_sale`.

## 4. Таблица `order_item` (Состав заказа)

Связывает заказы и товары, указывая количество и цену на момент покупки.

| Поле | Тип | Описание | Примечания |
|------|-----|-----------|-------------|
| `order_item_id` | SERIAL (INT) | Уникальный идентификатор строки заказа | Первичный ключ |
| `order_id` | INT | Идентификатор заказа | Внешний ключ → `orders(order_id)` |
| `product_id` | INT | Идентификатор товара | Внешний ключ → `product(product_id)` |
| `quantity` | NUMERIC(10,2) | Количество товара в единицах (штуки, кг) | |
| `price_at_sale` | NUMERIC(10,2) | Цена одной единицы товара на момент оформления заказа | Копируется из `product.price` в момент создания заказа |

**Связи:**
- Каждая строка принадлежит одному заказу (`N : 1` к `orders`).
- Каждая строка ссылается на один товар (`N : 1` к `product`).

**Уникальность:**  
В паре `(order_id, product_id)` не должно быть дубликатов (можно добавить уникальное ограничение, но не обязательно, так как идентификатор строки уникален).

---

## 5. Сводка связей между таблицами

| Отношение | Тип | Пояснение |
|-----------|-----|------------|
| `client` → `orders` | **1 : N** | Один клиент делает много заказов. Заказ не может существовать без клиента (`ON DELETE CASCADE`). |
| `orders` → `order_item` | **1 : N** | Один заказ содержит несколько товарных позиций. При удалении заказа каскадно удаляются его строки. |
| `product` → `order_item` | **1 : N** | Один товар может входить в много заказов. При удалении товара (**`ON DELETE RESTRICT`**) запрещено удалять товар, если он есть в заказах. |
