# Summer Practice — Интернет-магазин

REST API интернет-магазина для летней практики. Серверная часть на **FastAPI + SQLAlchemy 2.0 (async) + PostgreSQL**, разворачивается через **Docker Compose**.

## 📋 Описание предметной области

Вы — сотрудник коммерческого отдела компании, продающей товары через интернет. Нужно отслеживать финансовую составляющую работы магазина.

**Сущности предметной области:**

- **Клиент** — ФИО, телефон, email, адрес, роль (`client` / `manager` / `admin`), `total_purchases_amount` (сумма покупок за всё время — определяет «постоянного клиента»).
- **Товар** — название, цена, единица измерения (`шт` / `кг` / `л`), описание, остаток на складе.
- **Заказ** — клиент, дата продажи, дата доставки, итоговая сумма (после скидки), статус.
- **Состав заказа** — товар, количество, **цена на момент покупки** (`price_at_sale`).
- **Корзина** — персональная корзина клиента (1:1 с `client`).
- **Доставка** — адрес, дата, метод, статус (1:1 с `orders`).
- **Оплата** — способ, сумма, статус (1:1 с `orders`).
- **Отзыв** — клиент + товар + оценка (1..5) + текст.

**Бизнес-правила:**

1. Цена товара не может быть отрицательной.
2. Количество товара в заказе больше нуля.
3. Сумма заказа = Σ(`price_at_sale` × `quantity`) по всем позициям.
4. Каждый заказ связан с конкретным клиентом и содержит хотя бы один товар.
5. **Клиент становится «постоянным» при сумме покупок ≥ 5000 руб.**
6. **Постоянный клиент получает скидку 2% на каждый новый заказ.**
7. Цена сохраняется в `order_item.price_at_sale` на момент оформления — изменение цены в `product` не влияет на уже оформленные заказы.
8. После оформления заказа `client.total_purchases_amount` увеличивается на сумму заказа.
9. Складской остаток уменьшается на количество заказанного товара.
10. Статусы заказа: `new → processing → shipped → delivered` (или `cancelled` из `new`/`processing`).

## 🏗 Архитектура

Приложение разбито на 3 слоя (согласно аналитике из `AnaliticWork/`):

```
                 ┌─────────────────────────┐
                 │      Клиенты            │
                 │ (покупатели сайта)      │
                 └──────────┬──────────────┘
                            │ HTTP/JSON (REST API)
                            ▼
                 ┌─────────────────────────┐
                 │   Backend (FastAPI)     │
                 │  - бизнес-логика        │
                 │  - скидки, заказы       │
                 │  - аутентификация JWT   │
                 └──────────┬──────────────┘
                            │ asyncpg (SQL)
                            ▼
                 ┌─────────────────────────┐
                 │   PostgreSQL 15         │
                 │   - 8 таблиц            │
                 └─────────────────────────┘
```

Веб-клиент и админ-панель (React/Vue) — отдельный слой, в этом репозитории не реализуются;Backend готов к интеграции с любым фронтендом по REST.

## 🚀 Быстрый старт (Docker)

### 1. Клонировать репозиторий

```bash
git clone https://github.com/s0195866/SummerPracrise.git
cd SummerPracrise
```

### 2. Настроить переменные окружения

```bash
cp .env.example .env
# При желании отредактируйте .env: пароль БД, JWT_SECRET и т.п.
```

### 3. Поднять сервисы

```bash
docker compose up -d --build
```

Поднимутся два контейнера:

- `postgres-db` — PostgreSQL 15
- `shop-backend` — FastAPI на `http://localhost:8000`

Backend при старте автоматически создаст все таблицы (см. `app/database.py:init_db`).

### 4. (Опционально) Заполнить БД тестовыми данными

```bash
docker compose exec backend python -m app.seed
```

Создаются 4 клиента (1 админ, 1 менеджер, 2 клиента), 5 товаров, 2 заказа, 3 отзыва.

### 5. Открыть документацию

- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
- Health: http://localhost:8000/health

## 🧪 Локальный запуск без Docker

```bash
cd backend
python -m venv .venv
. .venv/bin/activate
pip install -e .

# Запустить PostgreSQL (можно через docker compose up -d db)
export DB_HOST=localhost DB_PORT=5432 DB_NAME=summer_practice DB_USER=postgres DB_PASSWORD=postgres

uvicorn app.main:app --reload --port 8000
```

## ✅ Smoke-тест

В репозитории есть end-to-end smoke-тест (`backend/tests/smoke_test.py`), который прогоняет весь основной сценарий через in-memory SQLite:

```bash
cd backend
. .venv/bin/activate
python -m tests.smoke_test
```

Проверяется:

- Логин по JWT
- Каталог товаров
- Корзина (добавить / изменить / удалить)
- Оформление заказа со скидкой 2% для постоянного клиента
- Обновление `total_purchases_amount`
- Роли (клиент не может менять статус заказа, админ может)
- Статистика и отзывы

## 🧱 Схема БД

Расширяет `docs/db/db_create_v1.0.sql` (4 исходные таблицы) дополнительными сущностями для полной реализации `EndPoint.md`:

| Таблица      | Назначение                                              |
| ------------ | ------------------------------------------------------- |
| `client`     | Клиенты и сотрудники (role: client/manager/admin)       |
| `product`    | Каталог товаров                                         |
| `orders`     | Заказы                                                  |
| `order_item` | Состав заказа (с `price_at_sale` на момент покупки)     |
| `cart`       | Корзина клиента (1:1 с `client`)                        |
| `cart_item`  | Строки корзины                                          |
| `delivery`   | Доставка (1:1 с `orders`)                               |
| `payment`    | Оплата (1:1 с `orders`)                                 |
| `review`     | Отзывы клиентов на товары                               |

Подробная семантика — в `docs/db/db_semantics.md`.
